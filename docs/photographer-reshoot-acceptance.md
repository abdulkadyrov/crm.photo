# Приёмочный тест: фотограф, экспорт и досъёмка отсутствующих

Цель проверки: доказать на двух независимых устройствах, что повторная съёмка добавляется в прежнюю школу и класс, не создаёт дублей и не меняет монтаж на основном компьютере.

## Главное правило работы

Проект узнаётся не только по названию школы, а по постоянному внутреннему ID.

- Фотограф продолжает работу в том же проекте и том же классе.
- Если проект остался на телефоне — открыть его и доснять отсутствующих.
- Если проект удалён — сначала импортировать на телефон сохранённый прежний ZIP проекта, а затем доснимать.
- Не создавать школу заново с тем же названием: у неё будет новый ID.
- После досъёмки можно снова сделать полный экспорт проекта. На основном компьютере повторный импорт работает как безопасное объединение.

## Подготовка

Нужны два независимых хранилища:

1. Телефон или отдельный профиль браузера — фотограф `Рассул`.
2. Основной компьютер или другой профиль браузера — владелец/монтажёр.

Перед тестом на основном компьютере выполнить `Настройки → Импорт / экспорт → Экспорт всех данных` и сохранить резервный ZIP.

Тестовые данные:

- проект: `ТЕСТ — Бача-Юрт`;
- класс: `1А`;
- ученик 1: `Адам Тестовый` — присутствовал;
- ученик 2: `Аминат Тестовая` — отсутствовала;
- одна настоящая тестовая фотография для каждого ученика.

Желательно сначала передать на телефон рабочую конфигурацию владельца и выбрать профиль `Рассул`. Тогда ID сотрудника и его статистика будут одинаковыми на обоих устройствах.

## Тест 1. Первая съёмка и первая передача

На телефоне:

1. Выбрать профиль `Рассул`.
2. Создать проект `ТЕСТ — Бача-Юрт` и класс `1А`.
3. Добавить обоих учеников.
4. Добавить фото только `Адаму Тестовому`. `Аминат Тестовая` остаётся без фото.
5. Экспортировать весь проект.
6. Сохранить ZIP и не удалять его до полного завершения школы.

На основном компьютере:

1. Импортировать ZIP как проект.
2. В предпросмотре должно быть: `+1` проект, `+1` класс, `+2` ученика, `+1` медиа.
3. Завершить импорт.
4. Убедиться, что проект один, класс один, Адам имеет фото, Аминат — нет.
5. Открыть профиль Рассула: должно быть одно сохранённое фото и один снятый ребёнок из двух.

## Тест 2. Защита монтажа на основном компьютере

На основном компьютере:

1. Создать готовую работу/монтаж для Адама.
2. Установить заметный статус, например `Напечатано`, если он доступен в вашем потоке.
3. Скачать готовый JPG или сделать контрольный скриншот.
4. Записать имя файла и визуально заметную деталь результата.

Эта работа является контрольной: после досъёмки она должна остаться без изменений.

## Тест 3. Досъёмка без удаления проекта

На телефоне:

1. Открыть существующий проект `ТЕСТ — Бача-Юрт`.
2. Открыть существующий класс `1А`.
3. Открыть существующую карточку `Аминат Тестовая`.
4. Добавить её новую фотографию.
5. Снова экспортировать весь проект.

На основном компьютере:

1. Ещё раз импортировать проект.
2. Вверху предпросмотра должна появиться надпись `Безопасное объединение досъёмки`.
3. Ожидаемые новые данные: `+0` проектов, `+0` классов, `+0` учеников, `+1` медиа.
4. Для конфликтов по умолчанию должно стоять `Безопасно объединить (рекомендуется)`.
5. Завершить импорт.

Проверить после импорта:

- проект по-прежнему один;
- класс `1А` по-прежнему один;
- учеников по-прежнему двое;
- у Аминат появилась новая исходная фотография;
- фото Адама осталось на месте;
- готовый монтаж Адама визуально совпадает с контрольным файлом/скриншотом;
- статус и локальные изменения на основном компьютере не откатились;
- в профиле Рассула стало два фото, `2/2` снятых детей, осталось `0`;
- класс считается пройденным.

## Тест 4. Повтор того же ZIP

На основном компьютере второй раз импортировать тот же ZIP досъёмки.

Ожидаемый результат:

- новых проектов, классов, учеников и фотографий не появилось;
- количество всех сущностей осталось прежним;
- монтаж не изменился;
- статистика Рассула не удвоилась.

Это проверка идемпотентности: один и тот же архив можно случайно выбрать повторно без образования дублей.

## Тест 5. Если фотограф уже удалил проект

На телефоне:

1. Импортировать сохранённый ZIP из теста 1.
2. Убедиться, что восстановились прежний проект `ТЕСТ — Бача-Юрт`, класс `1А` и карточки учеников.
3. Добавить фото отсутствующему ребёнку именно в восстановленной карточке.
4. Снова экспортировать проект.

На основном компьютере повторить проверки из теста 3.

Правильный результат — тот же проект дополняется. Новый проект создавать не нужно.

## Тест 6. Защита от случайного второго проекта

Отдельно проверить ошибочный путь:

1. На телефоне создать новый проект с тем же названием `ТЕСТ — Бача-Юрт`, не восстанавливая старый ZIP.
2. Экспортировать его.
3. Попробовать импортировать на основной компьютер.

Ожидаемый результат:

- приложение предупреждает: `Похожая школа уже есть, но ID проекта другой`;
- кнопка импорта заблокирована;
- для продолжения нужно явно отметить, что это действительно отдельный проект;
- для обычной досъёмки импорт следует отменить и восстановить прежний ZIP на телефоне.

## Тест 7. Большой реальный класс

На копии реального проекта с более чем 30 существующими записями повторить импорт досъёмки.

Ожидаемый результат:

- безопасный режим применяется и к конфликтам после первых 30 строк;
- ни одна скрытая строка не обновляется принудительно;
- новые фото добавляются, готовые работы и статусы остаются прежними.

## Критерий готовности

Сценарий принят, если пройдены все проверки:

- первый импорт создаёт проект;
- досъёмка дополняет тот же проект;
- повтор одного ZIP не создаёт дублей;
- готовые работы и монтаж не меняются;
- чеклист получает новый файл без отката более позднего статуса;
- статистика фотографа учитывает новые фото и пройденные классы один раз;
- архив с тем же названием, но другим ID не создаёт второй проект без явного подтверждения.

Если любой пункт не совпал, не удаляйте ZIP с телефона и не продолжайте рабочий импорт. Сохраните резервный ZIP основного компьютера, название проблемного архива и скриншот предпросмотра импорта.
