# Автоматическая синхронизация (v97)

CRM сначала сохраняет запись и задание отправки одной транзакцией IndexedDB.
При открытой CRM отправка запускается после изменения, восстановления сети,
возвращения во вкладку и раз в 20 секунд. Закрытый браузер не гарантирует фоновой
работы: сохранённая очередь продолжает передачу при следующем открытии.
Перед первым выездом устройство нужно подключить, войти и дождаться загрузки
назначенных проектов. Локальное хранилище браузера не следует очищать до отправки.

Постоянный UUID операции и сохранённый запрос позволяют повторить передачу после
потери ответа без второй записи. Файлы адресуются SHA-256 и физически хранятся
один раз; доступ проверяется для каждого проекта. Очередь хранит ссылки на
локальные записи, а не дополнительные копии фотографий. Отправленные архивы ZIP
остаются отдельными резервными снимками; импорт/экспорт сохранены.

Изменения разных полей объединяются относительно исходной версии. Разные снимки
в чеклисте объединяются. Если одно поле изменили по-разному, автоматическая
перезапись останавливается только для этой записи. Кнопка «Синхронизация» открывает
согласование: оставить свои изменения или принять серверную версию. Обе версии
сохраняются в истории на устройстве; сервер также хранит журнал принятых версий.
Удаление родителя с оставшимися дочерними записями не выполняется автоматически.

Права проверяет сервер при каждой операции. Финансовые поля, документы и настройки
доступны согласно роли; статусы оплаты сотрудников сохраняются. Локальные PIN,
операторы и настройки устройства не синхронизируются. Отзыв доступа блокирует
следующие обращения к серверу, но не стирает уже загруженные офлайн-данные.

Ранее опубликованные классы, дети и услуги обновляются в родительском API из
канонических записей. Новые классы по-прежнему публикует администратор отдельно.

## Развёртывание и перенос

Нужны server/app.py, parent_orders.py, sync_api.py и backup.py вместе с клиентом
v97. Миграции SQLite и IndexedDB добавляют таблицы без удаления старых данных.
Сервер: sync_records, sync_changes, sync_receipts, sync_blobs. Клиент: syncQueue,
syncMeta, syncHistory. Переносить всю CRM_DATA_DIR, включая crm.sqlite3, packages,
parent-media и sync-blobs; штатный backup.py включает эти данные. Не очищать
журнал и квитанции операций: они нужны для старых офлайн-устройств.

Проверки: npm run check; python3 -m unittest discover -s tests/server -v.
Интеграционный тест запускает настоящий WSGI API и два независимых IndexedDB,
проверяет офлайн-изменения, потерянное подтверждение, файлы и конфликт с восстановлением.
