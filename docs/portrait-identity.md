# Проверка сходства портрета

Модуль `js/services/portrait-identity.js` экспортирует `comparePortraitIdentity({originals: Blob[], result: Blob, signal, onProgress})`. UI находится в `js/ui/portrait-identity-panel.js`, подключение — в `showFinalWorkViewer`.

Используется локальная копия @vladmandic/face-api 1.7.15 (MIT): TinyFaceDetector, 68 tiny landmarks и face recognition. Библиотека и веса находятся в `third_party/portrait-face`. Источник: https://registry.npmjs.org/@vladmandic/face-api/-/face-api-1.7.15.tgz; документация https://github.com/vladmandic/face-api. Внешние API не вызываются. Фотографии и дескрипторы не записываются модулем на сервер или в IndexedDB. Кеш дескрипторов только в RAM, максимум 40 изображений; штатная PWA может кешировать публичные файлы модели.

Проверяются оригиналы только по studentId текущей работы. Фото результатов исключаются. `originalFinalImage` не используется как оригинал ребёнка: это может быть исходная сгенерированная работа. Результат берётся только из файла finalWorks или resultMediaId, без fallback на снятое фото.

Индекс: `100 * clamp(1 - EuclideanDistance(descriptorA, descriptorB), 0, 1)`, округление до 0.1. Итог — медиана расстояний всех пригодных оригиналов. Это не вероятность идентичности и не измеренная точность. Универсальных порогов одобрения нет, статусы CRM не изменяются. Большой разброс отмечается (более 0.2 в исходной шкале расстояния). Непригодные оригиналы перечислены отдельно. Уверенность детектора не является уверенностью идентичности.

Ограничения: модель не откалибрована на фотографиях детей из этой CRM. Ракурс, выражение, ретушь, свет, перекрытия и малое лицо могут влиять на результат. Оригинал должен содержать одно лицо. На результате допускается несколько кандидатов: выбирается кандидат с минимальной медианой расстояний до оригиналов ребёнка; если отрыв от второго меньше 0.06 — процент не выдаётся. Это эвристика выбора кандидата, не откалиброванный порог идентичности. Если лицо не найдено либо меньше 48 пикселей после уменьшения до 1400 px, процент не выдаётся. Нужен визуальный контроль. Это сравнение переданной пары/набора, не поиск ребёнка по базе.

Первое открытие загрузит около 8 MB публичных файлов. Инициализация и GPU-вычисления сериализованы; повторные проверки используют RAM-кеш по SHA256 содержимого. На устройствах без WebGL используется CPU; такой расчёт может быть медленным. Изображения ограничены 1400 px; detector inputSize 608, между шагами управление возвращается UI. Это браузерный async WebGL backend, не Web Worker. Закрытие viewer отменяет последующие этапы, активная GPU-операция завершается без записи результата в закрытый экран. Ошибка загрузки модели допускает повторную попытку.

Проверка качества перед выбором порога: собрать согласованные пары оригинал/результат и контрольные пары разных детей, отдельно оценить мальчиков/девочек, возраст, ракурс, размер лица. Сравнить распределения расстояний и ошибки. Не выбирать порог только по одному удачному примеру. Контрольные тесты математики и отмены: `tests/unit/portrait-identity.test.mjs`; реальное распознавание требует браузера и файлов моделей.

Обновление v314: несколько лиц/персонажей на готовом шаблоне больше не приводят к безусловному отказу. Сначала вычисляются дескрипторы оригиналов, затем оцениваются все пригодные кандидаты результата. Модель/версия входят в ключ оценки; старые неудачные проверки пересчитываются автоматически.
