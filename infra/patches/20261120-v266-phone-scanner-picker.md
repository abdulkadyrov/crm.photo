# Phone scanner service picker and sound (v266)

A paired phone decodes QR pixels locally, signals recognition and shows the current child's service previews. Tapping Add writes one selected work into the existing shared print selection; Mac refreshes on selection revision. Already-selected services remain marked, and repeat taps never increment copies. Numeric copies and final print/PDF preparation stay on Mac. Phone has Next QR, manual code input and a persistent sound toggle. Read, acknowledged save and duplicate use different brief audio signals; audio must unlock from a user gesture and never blocks saving.

Pairing still needs no CRM login on the phone. The short-lived token now grants access to the currently offered child/services, their previews and adding exactly those works. It does not grant project-wide CRM reads, arbitrary blobs, other works, print submission or account access. Owner activity, project access, session expiry, image version and correction state are checked server-side. The phone_camera_ui table is additive. Existing frame-only callers remain compatible.

Production overlay targets v265. Deploy standalone picker/feedback modules and the changed phone_camera.py; back up API and SQLite first, gracefully reload only crm-photo-api, and atomically switch a new immutable frontend release. The normal private blob delivery route supplies bounded previews. Roll back frontend symlink and backed-up API; the added table may remain.

Validation: 303 JavaScript tests and 93 server tests (two optional skips). Local package tests use a reduced upload cap due Mac free space, preserving the production guard. Chromium and WebKit fixtures at 319px cover real local QR decoding, camera relay, paired phone without login/cookies, two previews, phone selection of both exact services, duplicate protection, cloud/Mac sync, reload, next QR and remote disconnect. Audio unit tests verify gesture unlock, distinct signals and persisted mute; physical-phone speaker behavior is not established by browser tests.
